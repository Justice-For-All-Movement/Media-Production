# Scoped Consent decision HTTP boundary

Incomplete WIP. The existing public httpUseDecisionPort export from ./serve now captures each request and one exact service credential. Its decoded tenant/project/purpose must match the caller snapshot and its compartments must be a subset of that snapshot before transport. Decoded claims are a selection restriction, not signature authentication, original-human delegation, current membership or source-rights proof. E11 verifies signatures. The standalone token file remains one startup-selected scope; it cannot serve arbitrary caller scopes, refresh or prove current human authority. Hosts can supply a per-call credential callback directly; the credential checked is exactly the credential sent.

The engine-owned bounded transport and decision parser follow accepted Editorial PR2 (source285c69bb6f5ff34311012ae406731cd9482ab809): copied exact subjects/action/purpose/audience/territory/destination, no override/idempotency/retry, 200 subjects/64KiB request, 512KiB response/4096 chunks/fatal UTF8/independent bytes, one monotonic100..120000ms credential-transport-body-parse budget, sanitized failures and closed owned signals. Missing restrictions/time never become inferred empty restrictions/current time. Literal allow/deny/review are retained. No actual-use operation, provider send, publication or payment route is added.

Two native loopback tests reproduced the old behavior: foreign caller scope was sent using the static token and accepted as allow; a response missing restrictions and decision time also became allow. Five adapted transport/parser groups plus those two native regressions are being qualified. These are controlled local HTTP fixtures, not real E11/TLS or current rights acceptance. The existing renderer/worker/approval/export/cache semantics and their other security/host limits remain outside this adapter change. No render is dispatched by these tests. No schema/SQL adapter/dependency/vendor-kit/contracts changes. Original public15-engine/122-task design is copied byte-for-byte; private deployment policy excluded. PAM stays stopped at foundation; all test records private and fictional.
